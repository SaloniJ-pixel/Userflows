Workflow at a Glance

Stages
8 stages total Draft & Submit → System Routing → Waiting & Review → Decision → Escalation → Respond to Changes → Launch → Post-Launch
Key Actors
4 roles in the workflow
Brielle Chase Scott System
Primary Decision Maker
👤 Chase · The Approver Reviews all submissions and makes 4 possible decisions: Approve, Decline, Request Change, or Escalate
Timing
24-hour SLA Auto-escalation triggers if Chase doesn't respond within 24 hours
Escalation Path
👤 Scott · Senior Approver Only for large-budget decisions. Reviews same context + budget figure, then approves or declines.
Automation
⚙️ System handles routing Creates records, sends notifications, monitors timers, and auto-escalates when needed

Complete Stage Breakdown

Stage 1
Campaign is Ready
Brielle gets a prepared campaign in queue or creates one herself.
Confident
Stage 2
Submit
Brielle reviews and clicks Submit. System notifies Chase immediately.
Relieved — no manual tracking needed
Stage 3
Review
Brielle waits with countdown timer. Chase reviews on Launchpad with full context available.
Mildly anxious — has clarity on timing
Stage 4
Decision
Chase makes one of 4 decisions. System routes outcome. Brielle sees result immediately.
Chase can:
✓ Approve
✗ Decline
↻ Request Change
↗ Escalate
Stage 5
Escalation
If Chase escalates or doesn't respond in 24h, Scott reviews with budget context. Approves or declines.
Critical for large-budget decisions
Stage 6
Respond to Changes
If declined: archived. If changes requested: Brielle edits & resubmits (or system auto-updates if trusted).
In control — can act same day
Stage 7
Launch
Approval received. Brielle launches. 24-hour revert window opens for safety.
Excited — approved & ready
Stage 8
Post-Launch
All actors can see launch status and performance metrics. System can auto-launch if trusted.
Confident — loop closed cleanly
🔒 Trust-Gated Features
Auto-submit, auto-update, and auto-launch only after system builds trust in the requester
⚠️ Open Questions
Timing of Scott approval notification to Brielle. Revert window final state after 24h.
✅ Best Practice
All decisions require reason/note. Clear visibility at each step. No silent failures.

🔄 Flow Diagram

The exact branching logic — every decision point, system action, and loop. Follow the colored paths to see all possible outcomes.

7 Key Stages

1️⃣ Draft & Submit — Brielle prepares & submits
2️⃣ System Routing — Creates record, notifies Chase
3️⃣ Waiting & Review — Chase reviews with 24h timer
4️⃣ Decision — Chase decides (4 options)
5️⃣ Branch Outcomes — System routes based on decision
6️⃣ Resolution/Revise — Launch, decline, or revise
7️⃣ Escalation — Scott reviews if needed
Chase's Decision Tree
Approve: System updates status → approved. Notifies Brielle. Ready to launch.
Decline: System archives campaign. Notifies Brielle. Campaign ends.
Request Change: System notifies Brielle with change notes. Loops back to review. (System can auto-update if trusted)
Escalate: System routes to Scott. Chase card shows "Awaiting authorization". Scott reviews + decides.
🔒 Trust-Gated Automation
• Auto-Submit: System submits on Brielle's behalf (after trust built)
• Auto-Update: System reads Chase's change comments and resubmits (after trust)
• Auto-Launch: System launches approved decisions (after trust)
